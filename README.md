# 自定义考勤

面向飞书工作台的企业自建考勤应用。按员工、日期和工作时段指定打卡地点，例如上午在 A 园区、下午在 B 园区，或在指定楼栋周边 100 米内打卡。

考勤业务独立运行：飞书提供工作台入口、身份认证和客户端定位，本应用管理排班、打卡记录及统计。官方考勤同步是尚未实现的可选扩展，不是独立运行的前提。

## 功能

- 从飞书组织选择人员并自动绑定身份；普通用户、考勤组管理员、组织管理员三级权限。
- 考勤组管理，按负责组限制人员、排班、记录、统计与导出；权限变更立即生效。
- 管理首页按地点、考勤组、组织成员、排班、手机试打卡引导配置；普通用户直接使用个人打卡和排班。
- 新增地点自动通过飞书定位到附近；高德搜索、点选与半径预览，自动处理坐标，不要求输入经纬度。
- 班次模板、个人排班、多人多日期批量排班；每天支持 1～12 个不重叠时段。
- 上下班打卡，服务端校验身份、时间、地点、定位新鲜度和精度，防止重复提交。
- 个人飞书提醒可选提前 15 或 30 分钟；管理员查看记录默认延后 60 分钟，可自行调整。
- 正常、迟到、早退、缺卡及待打卡统计，最多查询 31 天，支持记录 CSV 导出。
- 飞书 OAuth 登录、H5 JSAPI 签名与手机定位，以及本地演示和不写入记录的规则试算。

## 运行与测试

需要 **Node.js 24 或更新版本**，服务端使用 Node 标准库；坐标转换组件已固定版本内置，无需执行 `npm install`。地图使用官方高德 JS API 2.0，需配置网页地图 Key 和安全密钥。

```sh
npm start
```

打开 <http://127.0.0.1:4173>。未配置飞书时仅监听本机，生成 A～D 四位示例员工、A/B 园区和 100 米楼栋围栏。示例坐标不代表真实办公场所，演示打卡会标记为演示来源。

```sh
npm test
```

自动测试覆盖核心规则、接口契约和服务行为，使用本地数据及模拟飞书请求。实际企业身份、手机定位、证书与部署环境仍需单独验证。

`npm start` 自动读取 `.env`。参考 [.env.example](.env.example) 配置；如需不加载该文件运行本地演示，可执行 `node server.mjs`，并确保终端环境没有注入飞书配置。

## 飞书与部署

配置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`BASE_URL`、`ADMIN_OPEN_IDS` 后启用飞书身份认证；缺少必需配置会阻止启动。正式模式使用独立数据文件，初始不加载演示员工与坐标。App Secret 仅存放在服务端，不要提交到仓库。

部署需要员工设备可访问、证书受信任的 HTTPS 根地址，以及单实例运行的持久存储。组织管理员管理全部组及公共地点、班次和角色；考勤组管理员仅管理所负责组的成员、排班、记录与导出；普通用户仅查看个人排班、记录、统计并为本人打卡。服务重启后需重新登录。

## 规则与限制

- 日期和时间统一采用 `Asia/Shanghai`。每个工作时段包含上班、下班两个打卡节点。
- 上班窗口为开始前 60 分钟至时段结束前；下班窗口为时段开始至结束后 120 分钟，且须在排班当天。迟到、早退按分钟判定。
- 定位必须明确提供 WGS84 或 GCJ-02；服务端转换到地点坐标系后计算距离，保存原始坐标及各自坐标系。精度不超过 `min(半径, 100米)`，且 `距中心距离 + 定位误差 ≤ 半径` 才通过。
- 已有打卡记录的排班不可修改或删除；记录保留当时规则快照。模板修改不回写已生成的排班。
- 缺卡在允许打卡窗口结束后计算；未到截止时间的节点记为待打卡，不据此计算旷工天数或薪资。
- 位置校验仅证明打卡时刻的定位结果，不能证明持续在岗、所在楼层或硬件级防伪。
- 当前不支持跨日班次、请假/加班审批、补卡审批、假期余额、薪资计算及 Wi-Fi/人脸防作弊，也不宣称与官方考勤全部功能一致。

演示数据保存到 `data/demo.json`，正式数据保存到 `data/attendance.json`。当前采用单 Node 进程 JSON 文件存储与原子替换写入，不能由多个实例共同写同一文件。请使用持久磁盘并定期备份；需要多实例时应先迁移数据库。

## 代码结构

- `server.mjs`：HTTP 服务、权限、会话和数据持久化。
- `access.mjs`：三级权限、考勤组数据范围与旧数据迁移。
- `domain.mjs`：排班验证、地理距离及打卡判定。
- `schedule-tools.mjs`：班次模板与考勤节点统计。
- `feishu.mjs`：飞书身份、通讯录、H5 JSAPI 与应用消息。
- `reminders.mjs`：提醒偏好、排班时点、去重与受限重试。
- `public/`：管理端与员工打卡页，无构建依赖。
- `tests/`：规则、接口契约和服务测试。

旧版数据首次启动时迁移为版本 2，原人员及历史记录归入“默认考勤组”。部署前备份数据；回退旧程序时须一并恢复迁移前备份。地图底图来自高德，依赖有效配置和客户端网络；正式使用前仍须实测现场中心与边界。
